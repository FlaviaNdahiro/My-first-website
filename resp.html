How this website works

A complete walkthrough of the build: every file, every region of the layout, every section of the stylesheet, and what each page on the site is actually demonstrating. Written for the person who has to change it in six months.

1. Overview

The project began as six unrelated practice files, each opened on its own. They are now a single website with shared navigation, one stylesheet and a consistent layout.

The organising idea is simple: the 5 × 5 grid exercise from the Grid lesson was never really an exercise — it was a dashboard. So it was promoted from a demo to the actual chrome of the site. Every lesson page now lives inside it.

Constraints. HTML and CSS only. No JavaScript, no build step, no dependencies, no images. Open any file directly in a browser and it works.

2. The files

my-first-website/ ├── index.html — intro / landing page (no dashboard shell) ├── dashboard.html — the overview page ├── index2.html — CSS selectors lesson ├── flex.html — flexbox lesson ├── grid.html — grid lesson (the layout explained) ├── form.html — registration form ├── docs.html — this page └── css/ └── styles.css — the one stylesheet, ~1400 lines

Every HTML file links the same stylesheet with a relative path: 

<link rel="stylesheet" href="css/styles.css" />
Why relative, not /css/styles.css? A leading slash means “from the root of the server”. When you open a file straight from disk with file://, that root is the root of your hard drive, so the stylesheet silently fails to load and the page appears unstyled. The relative path works both from disk and from a server.

3. Two page shells

The site uses two different page structures, on purpose.

The intro shell — index.html only

A landing page has one job: say what the site is and send you somewhere useful. It does not need a sidebar, a history panel or a user card, so it does not have them. Instead it is a single centred column of full-width bands: 

<body class="intro-page">
  <header class="intro-header"><div class="wrap">…</div></header>
  <main>
    <section class="hero"><div class="wrap">…</div></section>
    <section class="band"><div class="wrap">…</div></section>
    <section class="band band-tint"><div class="wrap">…</div></section>
  </main>
  <footer class="intro-footer"><div class="wrap">…</div></footer>
</body>

Each section stretches edge to edge so its background colour can run the full width of the window, while the .wrap inside it keeps the text in a readable column: 

.wrap {
  width: min(960px, 100% - 40px);
  margin-inline: auto;
}

That one declaration is the whole trick. min() picks whichever is smaller: 960px on a wide screen, or the full width minus a 20px gutter on each side when the window is narrow. It replaces a max-width, a padding and a media query with a single line, and it can never produce a horizontal scrollbar.

The dashboard shell — every other page

The remaining six pages share one structure. Only the topbar text and the <main> content differ between them: 

<body>
  <a class="skip-link" href="#main">Skip to main content</a>
  <div class="app">
    <aside class="sidebar">…</aside>
    <header class="topbar">…</header>
    <main class="main panel" id="main">…</main>
    <section class="history">…</section>
    <section class="profiles">…</section>
    <section class="userinfo">…</section>
    <footer class="footer">…</footer>
  </div>
</body>
The cost of no build step. With no JavaScript and no templating, the sidebar and the three side panels are copied into every file. Change the navigation and you change it in six places. That is the honest trade for a site that needs nothing installed to run — and it is the first thing a template engine or an include would fix.

4. The layout grid

.app is the only element that defines the page layout. Everything else just says which slot it belongs in. 

.app {
  display: grid;
  gap: var(--gap);
  padding: var(--gap);
  min-height: 100vh;
  grid-template-columns: var(--side-w) 1fr 1fr var(--aside-w);
  grid-template-rows: auto 1fr auto auto;
  grid-template-areas:
    "side  nav   nav   nav"
    "side  main  main  hist"
    "side  prof  prof  user"
    "side  foot  foot  foot";
}

Read the quoted block as a picture of the page. Four strings are four rows; four words per string are four columns; a name repeated across neighbouring cells means that region spans them.

The columns

var(--side-w)
A fixed 240px sidebar. Navigation should not change width as you move between pages.
1fr 1fr
Two flexible columns for the main content. Two rather than one so the bottom row can split into a wide profile panel and a narrower user card.
var(--aside-w)
A fixed 300px rail for the history panel.

The rows

auto
The topbar takes exactly the height of its content.
1fr
The main row absorbs every remaining pixel, so a short page still fills the screen instead of leaving the footer floating in the middle.
auto auto
The profile/user row and the footer, each as tall as they need to be.

Assigning an element to a region takes one line each:

.sidebar  { grid-area: side; }
.topbar   { grid-area: nav;  }
.main     { grid-area: main; }
.history  { grid-area: hist; }
.profiles { grid-area: prof; }
.userinfo { grid-area: user; }
.footer   { grid-area: foot; }
Why named areas instead of line numbers? The original demo used grid-column: span 3 / span 3; grid-column-start: 2; — correct, but unreadable, and every breakpoint means recalculating numbers by hand. With named areas a breakpoint is just a new picture, and the panels follow it automatically.

5. The six regions

Each region is a plain HTML element with one job. They map directly onto the boxes in the original grid sketch.

.sidebar — navigation

The brand, the page list and a short note. On desktop it is sticky, so it stays in view while a long article scrolls past: 

.sidebar {
  position: sticky;
  top: var(--gap);
  align-self: start;                        /* don't stretch to row height */
  max-height: calc(100vh - (var(--gap) * 2));
  overflow-y: auto;                         /* scroll if the list grows */
}

align-self: start matters. Without it the sidebar stretches to fill its grid area, and a sticky element that is already as tall as its container has nothing to stick to — it simply scrolls away.

The current page is marked with aria-current="page" rather than an .active class. It is a real attribute that screen readers announce, and it styles just as easily: 

.side-nav a[aria-current="page"] {
  background-color: var(--navy-600);
  border-left-color: var(--blue-300);
}

.topbar — page title and actions

A flex row: the page title and breadcrumb on the left, buttons on the right. flex-wrap: wrap lets the buttons drop to a second line before anything is squeezed. Each lesson page puts previous/next links here, so the site can be read straight through.

.main — the content panel

The only region whose content changes from page to page. It carries id="main", the target of the skip link, and the .panel class for the shared white-card look.

.history — the right-hand rail

An ordered list of the lessons, numbered with a CSS counter rather than the browser's default markers, so the numbers can be styled as circles: 

.history ol { counter-reset: hist; list-style: none; }
.history li { counter-increment: hist; }
.history li::before { content: counter(hist); /* the circle */ }

.profiles — the study group

Avatars are CSS circles with initials inside — no image files, so nothing to load and nothing to go missing. Each circle is aria-hidden="true" because the person's name is already written next to it; announcing “DM” before “Derrick M.” would only be noise.

.userinfo — the details card

A description list. <dl> is the right element for label/value pairs, and a two-column grid puts each <dt> beside its <dd> without any extra markup: 

.userinfo dl {
  display: grid;
  grid-template-columns: auto 1fr;
  gap: 8px 16px;
}

Demos are scoped

The selector lesson needs a rule like h3 + p. Written bare, that rule would reach into every heading on every page of the site. Prefixing it with the demo's own class keeps the experiment inside its box: 

/* not this */
h3 + p { background-color: antiquewhite; }

/* this */
.selector-demo h3 + p { background-color: antiquewhite; }

The same applies to .flex-demo and .grid-demo. This is the rule that made it safe to move the lessons out of their own files and into a shared stylesheet.

7. Design tokens

Every colour and key measurement is declared once on :root and referenced by name everywhere else. Changing the sidebar width or the accent colour is a one-line edit. 

:root {
  --navy-900: rgb(15, 35, 52);
  --navy-800: rgb(23, 42, 57);
  --navy-600: rgb(49, 73, 93);
  --blue-300: rgb(148, 183, 213);
  --cream:    antiquewhite;
  --brown:    brown;

  --side-w:  240px;
  --aside-w: 300px;
  --gap:     14px;
  --radius:  14px;
}

The palette is the one from the original grid sketch — the same five colours, just given names. brown was already the accent in the first stylesheet, so it stayed, and it is what marks every heading and primary button.

Because tokens are inherited custom properties, a media query can change the layout by redefining a value rather than by rewriting rules: 

@media (max-width: 1180px) {
  :root { --side-w: 210px; }   /* every rule using it updates */
}

8. Responsive behaviour

Three breakpoints, each one redrawing the area picture rather than hiding content. Nothing on this site is unavailable on a phone.

Above 1180px — four columns

"side  nav   nav   nav"
"side  main  main  hist"
"side  prof  prof  user"
"side  foot  foot  foot"

861px to 1180px — three columns

The history rail is the first thing to go; it drops below the main panel and its list becomes two columns so it does not become a long thin strip: 

@media (max-width: 1180px) {
  :root { --side-w: 210px; }

  .app {
    grid-template-columns: var(--side-w) 1fr 1fr;
    grid-template-areas:
      "side  nav   nav"
      "side  main  main"
      "side  hist  hist"
      "side  prof  user"
      "side  foot  foot";
  }

  .history ol {
    display: grid;
    grid-template-columns: repeat(auto-fit, minmax(220px, 1fr));
  }
}

Up to 860px — one column

Everything stacks in reading order, and the sidebar stops being a sidebar. Note that the topbar comes first: on a phone you want to know what page you are on before you see the menu. 

@media (max-width: 860px) {
  .app {
    grid-template-columns: minmax(0, 1fr);
    grid-template-areas:
      "nav" "side" "main" "hist" "prof" "user" "foot";
  }

  .sidebar { position: static; max-height: none; }

  .side-nav ul {
    flex-direction: row;   /* was a column */
    overflow-x: auto;      /* swipeable strip of pills */
  }

  .side-nav a { white-space: nowrap; }
}
minmax(0, 1fr), not 1fr. A grid column sized 1fr refuses to shrink below the widest thing inside it. One long line of code would push the whole page sideways. minmax(0, 1fr) allows the column to shrink, and the overflow is then handled where it belongs — inside the code block.

Below 560px — the demos simplify

Five equal grid columns on a phone would be unreadable, so the grid demo stacks into a single column and the span rules are switched off: 

@media (max-width: 560px) {
  .grid-demo {
    grid-template-columns: 1fr;
    aspect-ratio: auto;
  }
  .grid-demo > div {
    grid-column: auto !important;
    grid-row: auto !important;
  }
}

This is the one place in the stylesheet using !important. The span declarations are equally specific, so without it the later rule would not win.

Reflow without media queries

Card decks and the form's field pairs do not use breakpoints at all. They wrap on their own when the space runs out: 

.cards, .form-row {
  display: grid;
  grid-template-columns: repeat(auto-fit, minmax(230px, 1fr));
  gap: 14px;
}

auto-fit fits as many 230px-minimum columns as there is room for, then stretches them to fill the leftover space. Two columns become one automatically, at whatever width that happens to be — including inside a narrow panel on a wide screen, which a viewport-based media query cannot detect.

Things that are allowed to be wider

The page body must never scroll sideways, but three things legitimately can, each inside its own scrolling container: <pre> code blocks, .table-wrap around wide tables, and the mobile nav strip. Everything else is constrained.

Fluid type and spacing

body   { font-size: clamp(0.95rem, 0.9rem + 0.2vw, 1.05rem); }
.hero h1 { font-size: clamp(1.9rem, 1.3rem + 3vw, 3.2rem); }
.panel { padding: clamp(16px, 1rem + 1vw, 28px); }

clamp(min, preferred, max) scales smoothly between two bounds instead of jumping at a breakpoint. Keeping a rem in the middle value means the text still responds when someone raises their browser's default font size — a pure vw value would ignore that.

9. Page by page

index.html — introduction

The landing page, and the only one without the dashboard shell. A header, a gradient hero with two calls to action, a grid of six cards linking to everything else, a numbered “how it is built” list, and a footer. Each card is a single <a> wrapping its whole content, so the tap target is the entire box rather than a three-word link.

dashboard.html — overview

The first page using the shell. Four stat tiles, six lesson cards and a short explanation of the layout. It exists to show the six regions working together with real content in them.

index2.html — CSS selectors

Descendant (.card p), child (.card > p) and adjacent sibling (h3 + p), with a live demo and a reference table. The demo paragraphs deliberately carry no classes: the point is that the selectors do the choosing. Originally this file had no styles at all — the rules it describes were never written — so the demo now actually demonstrates something.

flex.html — flexbox

Four boxes in a flex container, where the second has order: 2 and flex: 1 1 100px so you can see reordering and growth at once. Tables cover the container properties and the item properties separately, because that division is the thing people most often get wrong.

grid.html — CSS grid

The self-referential page: it shows the original 5 × 5 sketch, then the named-area rewrite that the surrounding layout actually uses, then the breakpoints. Reading it inside the layout it describes is the point.

form.html — registration

Name, email, phone, a subject select, a radio group in a fieldset, and a message textarea. Fields pair up two-across on wide screens and stack on narrow ones with no media query. Everything it validates, the browser validates.

docs.html — this page

A table of contents of same-page anchors, then one .doc-section per topic. Each section has an id, so any heading here can be linked to directly.

10. Patterns worth reusing

Six small techniques carry most of the weight in this stylesheet.

min() for widths
width: min(960px, 100% - 40px) — a centred column with gutters, in one line, that can never overflow.
auto-fit + minmax
Grids that rewrap themselves based on the space they actually have, not the size of the window.
clamp()
Type and padding that scale smoothly between a floor and a ceiling instead of stepping at a breakpoint.
Named grid areas
A layout you can read as a picture, and a breakpoint that is just a different picture.
Custom properties
One place to change a colour or a width; media queries can redefine them instead of rewriting rules.
CSS counters
Numbered circles in the history list and the intro steps, with no numbers hard-coded in the HTML.
What is deliberately absent. No CSS framework, no utility classes, no resets beyond four lines, no icon font, no web font, and no JavaScript. Each of those would have been a dependency to learn and maintain before the layout itself could be understood.

11. Accessibility decisions

Skip link
Every page starts with a link to #main, hidden off-screen until it receives focus. Without it, a keyboard user tabs through the whole sidebar on every page.
Visible focus
A brown :focus-visible outline everywhere. The original form CSS had outline: none, which leaves keyboard users unable to see where they are.
aria-current
Marks the current page in the navigation for assistive technology, and doubles as the styling hook.
Label/id pairs
Every form control's for matches a real id. A for that points at nothing leaves the field with no accessible name at all.
Landmarks
header, nav, main, aside, footer — so the page can be navigated by region rather than by scrolling.
aria-hidden avatars
The initials in each circle are decorative; the name is already written beside them.
Reduced motion
A prefers-reduced-motion block switches off transitions for anyone who has asked their system for less movement.
Colour contrast
White text sits on the dark navies; the pale blue and cream panels use dark text instead.

13. Extending the site

Adding a page

  1. Copy any lesson page — flex.html is the smallest — and rename it.
  2. Change the <title>, the <meta name="description">, the topbar heading and the breadcrumb.
  3. Replace the contents of <main>.
  4. Add the page to the sidebar list and the footer nav in all seven files, and move aria-current="page" onto the new page's own link in its own copy.
Step 4 is the one that gets forgotten. If a page's sidebar disagrees with the others, that is why.

Changing the look

Edit the tokens in section 1 of the stylesheet rather than hunting through the rules. The accent colour, the navy shades, the sidebar and rail widths, the gap and the corner radius are all defined once.

Changing the layout

Redraw grid-template-areas in section 3, and redraw it again in each breakpoint in section 13. As long as the six region names stay the same, no other rule needs touching. To move the history rail to the left, for instance, swap the words: 

grid-template-areas:
  "side  nav   nav   nav"
  "side  hist  main  main"   /* hist now sits left of main */
  "side  prof  prof  user"
  "side  foot  foot  foot";
grid-template-columns: var(--side-w) var(--aside-w) 1fr 1fr;

Adding a lesson demo

Give it its own class and scope every rule to it, the way .flex-demo, .grid-demo and .selector-demo do. An unscoped element selector in a shared stylesheet will eventually reach a page you were not thinking about.

14. Running it locally

Because the paths are relative, double-clicking any HTML file works. A local server is still worth using — it matches how the site will actually be served, and it makes the browser's developer tools behave normally: 

cd my-first-website
python3 -m http.server 8777
# then open http://localhost:8777/

To check the responsive behaviour, open developer tools (F12), switch on the device toolbar (Ctrl + Shift + M) and drag the width through 1180px and 860px. The whole site is static, so it can be published by copying the folder to any host.

One thing to verify after every change: at 400px wide the page must not scroll sideways. If it does, something inside a 1fr column is refusing to shrink — the fix is usually minmax(0, 1fr) on the column, or an overflow-x: auto wrapper around the wide element.
